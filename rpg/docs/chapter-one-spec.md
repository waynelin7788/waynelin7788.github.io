# 第一章製作規格：潰堤前夜

> 狀態：RPG 版提案規格｜人物內在動機與第一章新情節均為新增設定，等世界觀確認後再視為正式內容。

## 1. 章節目的

第一章要讓玩家在可控的短流程裡體會三件事：有限時間迫使玩家取捨；同伴對「該先救誰、該守住什麼」有不同答案；準備方式會改變遭遇戰支援與章末代價。章末不判定單一正解，而把玩家選擇轉成第二章的資源、信任和未解問題。

玩家身份統一採核心企劃的暫定稱呼「凡人星幽調律者」。開場可保留「以元素繫牌引導共鳴」作為技藝，但「最後一位元素繫牌者」在原型完成世界觀統整前不採用。

## 2. 核心同伴人物卡

### 英格瓦・龍心

- **既有依據：**古龍遺跡成員、前排護衛，使用「巨龍之肋」守護戰線；與岩元素有關。
- **外在印象：**沉著、少說話、做事先看退路。他會先站到危險和隊伍之間，再確認大家是否跟上。
- **想要：**讓村民與隊伍都活著離開界碑村，並保留一條可重新接近界碑的路。
- **害怕：**在錯誤的時刻撤退，讓失去保護的人承受後果。
- **盲點：**容易把「自己留下來承受」當作已經解決問題；需要學會防守也包含替別人打開退路。
- **說話方式：**短句、具體指令；談責任與位置，不使用抽象口號。
- **關係節點：**與他巡查防線、練習守線，可提升信任並解鎖「堅忍支援」。章末若封鎖界碑，他願意留守；若撤離優先，他會要求玩家承諾回來處理界碑。
- **本章變化：**玩家讓他看見「守線」也可以是保住撤離通道，而非要求每個人留下。

### 弗蕾亞・龍脈

- **既有依據：**古龍遺跡成員、治療護佑，使用「生命之龍脈」，與水元素有關。
- **外在印象：**溫和而有行動力；照顧人時不會等待別人批准，但很少承認自己也需要休息。
- **想要：**盡量讓每個人都有離開低地的機會，並確保傷者不會被當成撤離負擔。
- **害怕：**救援變成只統計成功人數，留下的人被敘事和制度一起遺忘。
- **盲點：**會把所有人的照護責任往自己身上攬，可能因此忽略界碑和整體防線的期限。
- **說話方式：**先點出眼前的人與具體需要，再提出請求；情緒直接但不煽情。
- **關係節點：**協助撤離或安置傷者可提升信任與撤離進度。若玩家選擇撤離優先，她會在下一章協助建立臨時收容點；若封鎖優先，她會追問那些尚未抵達高地的人。
- **本章變化：**玩家是否把照護工作視為主線行動，將影響她是否相信隊伍會在危機後回頭。

### 法芙娜・暗瞳

- **既有依據：**古龍遺跡成員、遠程詛咒；既有描述指出她能在虛空龍息中看見深淵邊界。
- **外在印象：**安靜、觀察敏銳，談及深淵時不把未知直接等同邪惡。
- **想要：**分辨裂隙回響究竟是被困的存在、混沌殘響，還是引人接近的陷阱。
- **害怕：**把自己的理解投射到回聲上，讓好奇心替別人承擔代價。
- **盲點：**容易把「我能承受風險」誤當成「隊伍已經準備好承受風險」。
- **說話方式：**先描述觀察，再提出不確定的推論；避免神秘腔和全知預言。
- **關係節點：**共同勘查或追問回聲可獲得線索與信任。若玩家找到痕跡後選擇封鎖，她會追查封印下的聲音；若成功回應，她提供其他界碑的方向。
- **本章變化：**玩家是否願意求證並承認不確定性，決定她把調查當成共同工作或個人冒險。

## 3. 事件節點與條件

| 節點 | 進入條件 | 場景重點 | 寫入狀態 |
|---|---|---|---|
| C1-01 抵達村口 | 新章開始 | 界碑震動、村民未撤、三人提出不同優先順序 | `stance` 由玩家開場選項決定；相應能力或信任起始值 |
| C1-02 行動時段 | 開場選擇後 | 玩家選三項不同準備行動；每次後呈現場景、人物回應和時間變化 | `action_ids`、能力、信任、撤離進度、線索與訓練旗標 |
| C1-03 裂隙突破 | 三個時段結束 | 根據撤離與線索改變開場狀況及同伴台詞 | 記錄突破時撤離量；依線索決定是否辨認裂隙獸意圖 |
| C1-04 三回合遭遇 | C1-03 結束 | 每回合選守護、調律或牽制；下一回合先呈現上一行動的結果 | `battle_rescue`、`battle_stability`、`battle_pressure`、各行動次數 |
| C1-05 界碑抉擇 | 三回合遭遇完成 | 三方案皆有可理解代價，對應同伴的核心主張 | `chapter_choice`、方案結果、關係回應 |
| C1-06 尾聲 | C1-05 結束 | 把即時救援、界碑狀態與關係放進場景；留下第二章鉤子 | 結算存檔旗標與可回收線索 |

## 4. 旗標與回收方式

| 旗標／數值 | 設定時機 | 影響位置 | 後續回收 |
|---|---|---|---|
| `stance = measured / compassionate / curious` | 開場選擇 | 主角內在描述與一項起始能力／支援 | 第二章特定對話承接玩家一開始的做法 |
| `trace_found` | 查勘界碑或與法芙娜調查 | 遭遇前辨認裂隙獸、回應裂隙的解法 | 解鎖調查封印或辨識回聲來源的事件 |
| `evac_progress` | 撤離、安置傷者與遭遇守護行動 | 計算安全抵達高地的人數；改變弗蕾亞台詞 | 決定臨時收容點人口與可用醫療支援 |
| `resonance_practiced`／`resonance` | 調律訓練、開場態度、戰鬥調律 | 額外穩定界碑；降低回應回聲的代價 | 影響下一章的調律負荷與神獸共鳴事件 |
| `trust_ingvar / freya / fafnira` | 陪伴行動與章末方案 | 同伴支援、章末反應、替代對話 | 至少一個支線場景或可用隊伍技能 |
| `battle_rescue`、`battle_stability`、`battle_pressure` | 遭遇每回合 | 決定短期存活和界碑狀況 | 第二章以救援、維修或防守需求呈現 |
| `chapter_choice = seal / evacuate / answer` | 章末選擇 | 形成三條不同章尾 | 第二章開場地點、支援角色與第一個主線目標不同 |
| `echo_understood` | 回應回聲且持有線索／足夠洞察 | 決定回應是理解成功或承受未知反噬 | 成功取得界碑線索；失敗則帶著調律負荷尋求協助 |

重要原則：數值服務於場景，不以數字代替敘事。下一章至少要回收章末方案與一項前期準備；其餘旗標可透過人物台詞或局部支援回收，不必每個都長成獨立路線。

## 5. 章末方案對照

| 方案 | 即時保住 | 即時代價 | 主要角色回應 | 第二章入口 |
|---|---|---|---|---|
| 封鎖界碑 | 界碑村防線暫穩；若已調律，封印更完整 | 回聲被隔絕，封印下的狀況未知 | 英格瓦留下守線；法芙娜要求調查封印內部 | 從封鎖線出發，查明裂隙是否仍有活動 |
| 撤離優先 | 更多居民抵達高地；可依救援準備提高人數 | 界碑缺少看守，後續防線壓力上升 | 弗蕾亞建立收容點；英格瓦等待回防命令 | 從倖存者營地出發，處理資源與回防問題 |
| 回應回聲 | 有線索／能力時取得其他界碑方向 | 界碑穩定度可能不足；條件不足時調律者承受負荷 | 法芙娜同行調查；英格瓦要求先評估風險 | 循著回聲前往下一座界碑，或先尋找穩定調律的方法 |

## 6. 遭遇戰方案建議

**建議首版採用目標導向的選擇式回合戰鬥**：每回合選擇守護、穩定、牽制，並由前期行動和信任提供可讀的加成。這保留現有原型已展示的多目標取捨和故事回應，製作量也符合單人網頁垂直切片的範圍。

暫不把完整卡組構築當成 RPG 必要系統：它會拉高戰鬥、牌庫、平衡和 UI 工作量，也容易讓敘事行動被戰鬥系統搶走重心。若日後玩家回饋希望有更深戰術，下一個升級方向應先加入同伴技能與每回合有限的調律資源，再評估是否加入卡牌或位置戰場。

## 7. 技術與內容結構建議

- 對外試玩平台沿用純靜態網頁與 GitHub Pages，符合目前免建置、分享網址即可玩的原型。
- 事件、對話、選項、條件和旗標效果已移到獨立資料檔；後續新增章節沿用此結構，避免單一程式檔膨脹。
- 暫不引入框架或伺服器；先完成第一章重玩、分支回收與存檔格式，再依內容量決定是否需要升級工具。
- 預設本機儲存進度，並提供新週目／清除紀錄入口；不收集玩家個資。

## 8. 下一個製作里程碑

第一章事件與選項採資料驅動，三種主要結局及「理解／未能理解回聲」狀態會進入不同的第二章開場；章末進度存在玩家瀏覽器，第二章入口也有各自的首個任務抉擇。第一章已開始採用角色插畫與場景對話版面，並把所需輕量圖片放在 RPG 專案內。

下一階段先完成第一章圖畫版垂直切片，確認現有素材在桌機與手機上的呈現效果、敘事閱讀節奏和選項介面。試玩後再判斷是否需要新繪表情或場景插圖；確認呈現方向後，再把第二章入口延伸為完整章節，讓不同入口逐步匯入共同主線。
