## 測試方式

以 Node.js 載入遊戲實際的 `chapter-content.js` 與 `main.js`，在輕量 DOM 替身中呼叫遊戲內的章節切換、選項解析、結局與存檔續玩函式。每輪都由第五章尾聲按下實際註冊的「前往第六章」動作開始，確認切線結果，再逐階段走至結局。

瀏覽器不允許本次工作階段開啟本機 `file:` 網址，因此本紀錄驗證的是遊戲 JavaScript 流程函式，不包含實際瀏覽器畫面、圖片載入、版面或滑鼠操作測試。前五章也未逐項重跑；測試從第五章分歧接點開始。

## 測試中發現並修正

1. **替代章節的故事紀錄標題未識別。** 新章名帶有副標題，原紀錄只識別原本的「第六章」等名稱，導致章節標題與節標題缺失。已補上失星航路篇五章及新結局的紀錄標籤。
2. **航標石芯的可用次數前後矛盾。** 第六章說石芯裂開後只剩一次傳訊，第八章原文卻又寫成再次啟動，與第九章「僅剩一次」衝突。已把第八章改成讀取先前留下的刻度，不再消耗一次傳訊；第十章才使用最後一次。
3. **守望者與星噬者突然出席議盟。** 原路線第九章直接讓兩者現身，且沒有說明星噬者就是失名後的第一守護者。已在第八章加入檔案副本的身分線索，並在第九章補上兩者循民用航路與檔案回聲抵達、居民同意牠進入議盟的過程。
4. **未使用的航標狀態欄位。** 刪除沒有參與條件判定的計數欄位；改讓居民互助、保存證據與建立信任的累積結果，分別在結局尾聲反映出來。
5. **三種新結局原先共用同一存檔進度碼。** 結局頁可正確顯示，但存檔卡會把三種結局都標成同一分歧編號。已讓失星航路篇結局進度碼依結局分開記錄。

## 尚待決定的設計點

失星航路篇的三種結局目前都可在第十章直接選擇。前面的居民、證據與信任選項會改變結局後記，但不會封鎖任何一種結局。若希望結局必須由前面選擇解鎖，還需要另訂明確條件；本輪測試未擅自增加限制。
